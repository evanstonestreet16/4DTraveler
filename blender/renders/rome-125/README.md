# Rome 125 CE — POI proxy render handoff

**This directory is committed on purpose.** `blender/source/rome-125/renders/` is ignored (`*`) and holds
local scratch. This lane is the contract between Blender authoring and streetview generation, so everything
here is small, versioned, and safe to pull.

Blender authoring pushes proxy renders here. Streetview generation consumes them and writes finished
panoramas to `public/images/rome-125/`. Neither side edits the other's output.

## What a POI directory contains

| File         | Purpose                                                                                | Spec                                            |
| ------------ | -------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `proxy.png`  | img2img base. Structure and layout only; it is not meant to look good.                 | Equirectangular, 2048 × 1024, flat shading      |
| `depth.png`  | ControlNet depth conditioning                                                          | 16-bit grey, near = white, normalized per scene |
| `normal.png` | ControlNet normal conditioning                                                         | Camera-space normals                            |
| `ids.png`    | Per-entity flat colour mask. Used to verify the generated image did not move anything. | Colour ↔ entity map lives in `proxy.json`       |
| `proxy.json` | Camera, hotspot angles, entity list, prompt scaffold, source references                | See below                                       |

## Rules that keep the pipeline honest

1. **Hotspot angles are authoritative and frozen.** `src/utils/panorama.ts` places markers from `yaw`/`pitch`
   alone. If generation moves a building, the marker points at the wrong thing. Structure must survive.
2. **Generated output never invents architecture.** The model adds material, wear, light, atmosphere, people
   and vegetation. Anything a source could contradict comes from Blender.
3. **The seam must match.** Equirectangular left and right edges wrap. Check before accepting an image.
4. **Negative prompts come from the data, not from taste.** Anachronism exclusions are generated by querying
   entities whose inception postdates the scene year.
5. **Re-render freely.** Proxies are cheap. Never hand-patch a proxy; change the scene and regenerate.

## Accepting a generated panorama

- Marker check: re-project each `proxy.json` hotspot onto the generated image and confirm it lands on the same
  entity region as in `ids.png`.
- Seam check: the leftmost and rightmost pixel columns must be continuous.
- Anachronism check: nothing from the `negative` list is visible.
- Then package through `blender/scripts/package_rome_renders.py` so the manifest hash and provenance update
  together. Never copy an image into `public/images/` by hand.
